# Huy Finder — дизайн

Дата: 2026-09-19. Одностраничное веб-приложение ради шутки: ищет на карте места, где маршруты
самолётов складываются в буквы Х, У, И (показываем как Й) и в слово ХУЙ.

## 1. Цели и границы

- Стек: Vite, Vue 3, TypeScript, MapLibre GL, Vitest.
- Источники данных: генератор (по умолчанию, основной) и API Flightradar24 (тонкий адаптер,
  ключ из `.env`). Боевого ключа скорее всего не будет — адаптер пишется по формату ответа сендбокса
  и на живых данных не проверяется.
- Область поиска — видимая область карты.
- Показываем отдельные буквы с оценкой и слова из трёх букв с шкалой идеальности.
- Вне первой итерации: оформление, прогноз трека вперёд по курсу, история находок,
  сохранение между перезагрузками, Web Worker.

## 2. Что известно про API FR24 (проверено вручную 2026-09-19)

- Базовый адрес `https://fr24api.flightradar24.com/api/`. Заголовки: `Authorization: Bearer <ключ>`,
  `Accept-Version: v1`, `Accept: application/json`.
- `live/flight-positions/light?bounds=N,S,W,E` — позиции в прямоугольнике:
  `{ data: [{ fr24_id, hex, callsign, lat, lon, track, alt, gspeed, vspeed, squawk, timestamp, source }] }`.
- `live/flight-positions/full` — то же плюс рейс, тип, аэропорты.
- `flight-tracks?flight_id=` — трек рейса по точкам. Не используем.
- Сендбокс-ключ отдаёт одни и те же 2 самолёта, границы игнорирует. Для разработки бесполезен.
- CORS открыт (`access-control-allow-origin: *`), браузер ходит в API напрямую, сервер не нужен.
  Ключ лежит в клиенте — для шутки среди друзей допустимо.

## 3. Структура

```
src/
  data/
    FlightSource.ts   интерфейс: fetchPositions(bounds) → Promise<Position[]>
    Fr24Source.ts     адаптер API, ключ из VITE_FR24_KEY
    MockSource.ts     генератор
    random.ts         детерминированный генератор случайных чисел
  tracks/
    TrackStore.ts     склеивает позиции в треки по id, удаляет протухшие, обрезает длинные
  geometry/
    project.ts        широта/долгота → плоские метры вокруг центра области и обратно
    simplify.ts       Дуглас-Пекер: трек → отрезки
    segments.ts       пересечение, угол, расстояние точка-отрезок, проекция точки на отрезок
  detect/
    types.ts          Letter, Word, DetectOptions
    detectX.ts  detectU.ts  detectI.ts
    detectWord.ts
    analyze.ts        конвейер: треки → проекция → отрезки → буквы → слова
  map/
    geojson.ts        результат анализа → GeoJSON для слоёв
    MapView.vue       карта; слои: треки, буквы, дужка над И, слова
  ui/
    Controls.vue      источник (демо/API), интервал опроса, чувствительность, кнопки подсадки
    Findings.vue      минибар: лучшая находка, список слов, счётчик букв
  composables/
    useScanner.ts     цикл опроса и расчёта, реактивный результат
  App.vue
```

`geometry/` и `detect/` — чистые функции без Vue и карты. Карта и интерфейс только рисуют результат
`useScanner`.

### Типы

```ts
type Position = { id: string; lat: number; lon: number; heading: number; timestamp: number };
type Bounds = { north: number; south: number; west: number; east: number };
type Pt = { x: number; y: number };                     // метры в локальной проекции
type Segment = { a: Pt; b: Pt; trackId: string; id: string };
type LetterKind = 'X' | 'U' | 'I';
type Letter = {
  kind: LetterKind; score: number;                      // 0–100
  center: Pt; up: Pt; size: number;                     // up — единичный вектор «верх»
  segments: Segment[]; key: string;                     // key — отсортированные id отрезков
};
type Word = {
  letters: [Letter, Letter, Letter];                    // в порядке чтения
  text: string;                                         // 'ХУЙ', 'ЙУХ', ...
  correctOrder: boolean; score: number;                 // 0–100
  grade: 'perfect' | 'good' | 'crooked' | 'anagram';
  center: Pt; key: string;
};
```

## 4. Поток данных

`useScanner` выполняет шаг раз в N секунд: 5 с для генератора, 20 с для API.

1. Берём границы видимой области карты.
2. Источник возвращает `Position[]`.
3. `TrackStore.add(positions, now)`: точка добавляется в трек с этим `id`. Трек без обновлений
   10 минут удаляется. Трек длиннее 200 точек обрезается с начала.
4. Каждый трек проецируем в метры (центр проекции — центр области) и упрощаем Дугласом-Пекером
   с допуском 2 км. Получаем отрезки.
5. `detectX`, `detectU`, `detectI` получают все отрезки и порог чувствительности, возвращают буквы.
   `detectWord` получает буквы, возвращает слова.
6. Результат кладём в реактивное состояние. Карта перерисовывает слои.

Расчёт в главном потоке: при 300 треках это сотни отрезков, счёт занимает миллисекунды.

## 5. Генератор (`MockSource`)

- Конструктор принимает зерно случайности. С одним зерном — одинаковая последовательность.
- При старте и при смене области (сдвиг более чем на половину ширины) создаёт 40–80 рейсов:
  случайная точка в границах, случайный курс, скорость 700–900 км/ч.
- На каждом `fetchPositions` рейсы продвигаются по курсу за прошедшее время. С вероятностью,
  дающей в среднем один поворот на рейс в 3–5 минут, курс меняется на 10–40°.
- Рейс, вылетевший за границы, удаляется, новый заводится на случайном краю области.
- `plantLetter(kind)` и `plantWord()`: создают 2–3 (для слова 7) рейса со стартовыми точками и курсами,
  чьи треки сложатся в букву или в слово ХУЙ. Размер буквы — 12% высоты области, скорость подсаженных
  рейсов 1200 км/ч, штрих дорисовывается за 1.5–2 минуты. Долетев до конца штриха, рейс исчезает
  (иначе продолжение линии испортит букву). К положению добавляется шум до 5% размера, к курсу ±2°.
  Слово ставится с случайным наклоном в пределах ±40° от севера.

## 6. Алгоритм распознавания

Все расчёты в плоских метрах. Два отрезка одного трека в одну букву не берём.
Порог показа буквы — 30%. Ползунок чувствительности сдвигает порог и все допуски ниже
в пределах ±30% от значений по умолчанию. Допуск упрощения ползунок не трогает.

### Х — пара отрезков

- Пересекаются.
- Угол 40–140°.
- Точка пересечения в 15–85% длины каждого отрезка.
- Длины отличаются не более чем в 3 раза.

Оценка: среднее из близости угла к 90° и близости пересечения к середине обоих.
Центр — точка пересечения, размер — средняя длина. Вектор `up` не определён (Х симметрична);
при сборке слова подстраивается под остальные буквы.

### У — длинный `A` и короткий `B`

- Конец `B` не дальше 10% длины `A` от самого `A`.
- Проекция этого конца на `A` попадает в 30–70% длины `A`.
- Длина `B` от 25% до 80% длины `A`.
- Угол 25–85°.

`up` смотрит от точки касания в сторону раздвоения (среднее направлений двух верхних лучей).
Оценка: близость угла к 50° и точки касания к середине `A`. Размер — длина `A`.

### И — тройка отрезков

- `L` и `R` почти параллельны: угол до 25°.
- Расстояние между ними 30–150% средней длины. Длины отличаются не более чем в 2 раза.
- Диагональ `D` соединяет концы: один конец не дальше 20% длины от одного края `L`,
  другой — не дальше 20% от противоположного края `R`.

Поиск: сначала все параллельные пары, затем для каждой пары ищем диагональ среди отрезков,
чьи концы попадают в нужные окрестности. `up` — так, чтобы диагональ шла снизу-слева
вверх-направо. Размер — средняя длина `L` и `R`.

Показываем как Й: над буквой рисуется дужка — отрезок длиной 40% ширины буквы, отступ 15% высоты.

### Слово — тройка букв X, U, I, по одной каждого вида

Условия отбора:
- `up` у У и И совпадают с допуском 35°. И центрально-симметрична, поэтому для неё подходит и `up`, и `-up`; общий `up` слова берётся у У, а `up` И разворачивается к нему.
- Центры лежат на одной прямой, перпендикулярной `up`, с отклонением до 50% среднего размера.
- Размеры отличаются не более чем в 2.5 раза.
- Расстояние между центрами соседних букв вдоль прямой — от 50% до 300% среднего размера.

Порядок букв читается вдоль прямой слева направо относительно `up`. `text` — буквы в этом порядке,
И записывается как Й. `correctOrder` — `text === 'ХУЙ'`.

Оценка: `0.6 × среднее оценок букв + 0.4 × аккуратность ряда`, где аккуратность — среднее из
четырёх величин: прямолинейность центров, совпадение `up`, равенство размеров, равенство зазоров.
Если порядок неверный — оценка умножается на 0.6.

Уровни (`grade`):

| Оценка | grade | Название |
|---|---|---|
| 90–100, порядок верный | perfect | Эталонный |
| 70–89, порядок верный | good | Годный |
| 40–69, порядок верный | crooked | Кривой |
| любая, порядок неверный | anagram | Анаграмма |

Слова с оценкой ниже 40 и верным порядком не показываем. Анаграммы показываем все.

Дубли: ключ буквы — отсортированные `id` отрезков, ключ слова — отсортированные ключи букв.
Одинаковые ключи схлопываются.

## 7. Отображение

- Треки: тонкие линии.
- Буквы: обводка отрезков буквы цветом по виду, подпись с буквой и процентом. У И — дужка сверху.
- Слова по уровням: perfect — жирная яркая обводка, крупная подпись, мигание;
  good — яркая обводка, подпись «ХУЙ»; crooked — тонкая обводка, приглушённый цвет;
  anagram — пунктирная серая обводка, подпись реальным порядком букв.
- Минибар (`Findings.vue`): сверху лучшее слово с полоской-шкалой, оценкой и названием уровня;
  список всех слов по убыванию оценки, у каждого полоска и `text`, клик — перелёт к слову;
  внизу счётчик букв: Х, У, Й.
- `Controls.vue`: переключатель источника (API недоступен без ключа, подпись «нет ключа»),
  интервал опроса, ползунок чувствительности, кнопки «подбросить букву» (Х/У/Й) и «подбросить слово».

Конкретные цвета, шрифты и раскладка — следующая итерация.

## 8. Ошибки

- Сеть или 5xx: плашка, повтор на следующем шаге. После трёх ошибок подряд интервал удваивается,
  максимум 2 минуты, сбрасывается после успеха.
- 401, 402, 403: опрос останавливается, плашка с текстом ошибки и кнопка «перейти в демо».
- Пустой ответ — не ошибка.
- Генератор ошибок не даёт.

## 9. Тесты (Vitest)

- `geometry/`: проекция туда и обратно; упрощение прямой в один отрезок и ломаной в несколько;
  пересечение отрезков, угол, расстояние точка-отрезок, проекция на отрезок.
- `detect/`, для каждой буквы: идеальная — оценка выше 90; искажённая — 30–90; не-буква
  (параллельные линии, Г, V, отрезки одного трека) — не находится.
- `detectWord`: идеальное ХУЙ — `perfect`, `correctOrder: true`; ЙХУ в ряд — `anagram`, оценка
  не выше 60; три буквы с разным наклоном — не находится; буквы не в ряд — не находится.
- `TrackStore`: склейка по `id`, удаление протухших, обрезка длинных.
- `MockSource`: одно зерно — одни позиции; рейсы движутся по курсу; после `plantWord()` и нескольких
  шагов `detectWord` находит слово с верным порядком.
- Компоненты карты и интерфейс — ручная проверка в браузере.
